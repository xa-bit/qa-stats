# qa-stats · QA 语料统计分析工具 — 项目设计方案

> 版本：v1.2（2026-11-08）
> 定位：QA 语料的**下游统计工具**。v1.0 面向家族 `q-a / q-a-factual` 产物；v1.1 起接受任意字段名未知的通用 QA jsonl，并升级为学科多标签分类；**v1.2 新增主流期刊标准学科树（双语标签：英文 label 最终口径 + 中文 zh 对照），调研与完整分类表见 [主流期刊分类标准调研.md](./主流期刊分类标准调研.md)**。
> 参考项目：[easy-dataset](https://github.com/ConardLi/easy-dataset)（ConardLi，AGPL-3.0）、[distilabel](https://github.com/argilla-io/distilabel)（Argilla，Apache-2.0）

2. PROMPT_VERSION v2 → v3（旧分类缓存自动失效，重跑分类按英文树增量重分类）。

## 0. v1.1 变更记录（相对 v1.0）

针对「不是所有 QA 文件都带标签、字段名未知」的现实，v1.1 补齐四块能力：

1. **结构探测（server/schema.js，新增）**——不再假设字段名已知：
   - **L-alias 别名层**：常见命名（query/response/thinking/cot/prompt/… 中英）归一命中，置信 0.95；
   - **L-feature 特征层**：字段值形态统计（问号率、疑问词率、中位长度、段落率、推导连接词率、唯一率、类型分布）打分到角色；同角色次高分接近胜者（差 ≤0.2）才视为真竞争并降置信，远弱候选不干扰；
   - **L-llm 仲裁层**：question/answer 任一缺失或置信 <0.75 → 把字段名+统计+样本发 LLM 判角色（白名单校验，非法字段/角色丢弃，程序别名高置信结果不被覆盖）；
   - 旁挂 `<stem>-schema.json`（含全字段统计与来源）；统计路径只用程序探测（零 LLM），分类任务/手动按钮才触发 LLM 仲裁；未映射文本字段进 `row.extra`，长度照统计不丢单。
   - flow 识别放宽：`factual`（有 reasoning/track）/ `research`（有 references）/ **`generic`**（其余）。
2. **学科多标签**（交叉学科的落地方式）：
   - cls 行升级 `subjects: [{l1,l2,confidence,source}]`（主学科在前）+ `subject`（=subjects[0]，向后兼容；旧文件读入自动规范化）；
   - 提示词 v2 内置**数量纪律**：绝大多数 1 个、确有交叉才 2 个、3 个为少见上限；LLM 超量 → 截断 + `tagsOutOfRange` → judge 重判或人审；人审多标签改判（1~maxSubjects，设置可调，默认 3）；
   - **树的约束与打标的分工**：树内二级唯一归属一级（校验强制，白名单无歧义）；学科交叉、方向交叉、一方向多学科，全部由**一道题打多标签**表达；统计层出学科共现矩阵与每题标签数分布监控「标签数量差别大」的不合理信号。
3. **标签库管理**（设计方案 §5 承诺的 M4 落地）：
   - `GET/PUT /api/taxonomy`（校验：树非空、标签唯一、必含兜底「其他」、二级不跨一级；保存 version 自增 → 分类缓存自动失效增量重分类）；
   - 预置两套学科树：**通用**（`taxonomy-general.json`，一级粒度参考中科院期刊分区大类 + JCR/ESI 学科归纳，14 一级）与**海洋气象领域**（原树）；Web 可加载预置到编辑器后另存；
   - **LLM 归纳建议稿**（`POST /api/taxonomy/propose`）：抽样 ≤80 条 → easy-dataset getLabelPrompt 同款范式产树 → 人工修订后保存，绝不直接生效；
   - Web「标签库」tab：树编辑（增删改/上移/描述）、「浏览完整标签信息」弹层（全标签表 + 旭日 + 共现热力 + 计数），导出走 **File System Access API `showSaveFilePicker()`**（系统保存位置选择框；不支持时退化 `a.download`），可存 CSV/JSON/单文件 HTML。
4. **配套**：扫描放宽到 `*.jsonl`（排除 `-cls.jsonl` 产物）；设置新增 `maxSubjects` / `autoSchema`；模型配置一键从家族项目（q-a-factual / q-a）导入；统计新增 `extraFields`（未知字段长度）、`flows.generic`；报告 CSV 14 个（新增 subject-cooccurrence / tags-per-qa），HTML 报告新增共现热力与标签数分布图；离线自测 47 项（新增 18 项覆盖以上全部）。

## 1. 背景与目标

### 1.1 流水线位置

现有家族流水线（research 轨与 factual 轨）：

```
pdf-md → md-clean → md-chunks(-factual) → chunks-q(-factual) → q-a(-factual) → human-verify
  （PDF转md）  （清洗）      （分块）              （问题生成）        （答案生成）      （人工核验）
                                                    ↓
                                            【qa-stats】★ 本项目
```

`q-a` / `q-a-factual` 的产物 `-qa.jsonl` 已经携带了较丰富的元数据（label / gaPair / track / reasoning / qCheck / eval），但**没有任何工具对语料做整体的统计透视**：学科覆盖是否均衡、内容类型分布如何、推理模型的思考长度呈现什么分布、与质量分的关系怎样——这些都只能靠人工抽查。qa-stats 补上这一环。

### 1.2 目标

1. **输入**：读取一个或多个 `-qa.jsonl`（research 与 factual 两种 schema 自动识别），零修改、旁挂式分析。
2. **分类**：对每条 QA 标注**学科**（二级树）与**内容类型**，采用"程序规则 + LLM"混合引擎，追求可校验的准确率（置信度、白名单约束、冲突仲裁、可抽样人审）。
3. **统计**：规模、学科分布、内容类型分布、思考长度分布（双口径：梳理后 / 原始）、质量分、截断率、交叉分析（学科 × 内容类型、长度 × 分数等）。
4. **输出**：表格（CSV / Markdown / Web 交互表）+ 图表（交互式 Web 仪表盘、单文件 HTML 报告、PNG 导出），一份"尽量全面"的语料体检报告。
5. **风格**：与家族项目一致——Node.js（server + web + scripts）、OpenAI 兼容 LLM 直连、文件型 jsonl 产物、CLI + Web 双入口、离线自测 `npm test`。

### 1.3 非目标（本期不做）

- 不重新生成 / 改写 QA（那是上游项目的职责）；
- 不做模型训练、不对接 HuggingFace Hub；
- 不替代 human-verify 的人工核验（但提供"分类人审队列"轻量复用其思想）。

## 2. 调研结论与借鉴点

两个参考项目的调研要点（已核对源码/文档，细节标注出处），以及各自对本设计的映射：

### 2.1 easy-dataset（15.1k★，Next.js + Prisma/SQLite）

| 其做法 | 事实依据 | qa-stats 借鉴 |
|---|---|---|
| **两级领域标签树**：从全部文档目录（TOC）一次性 LLM 归纳，一级 5–10 个、每级下二级 1–10 个，标签名 ≤6 字，带 "1 / 1.2" 编号，严格 JSON 输出 | `lib/llm/prompts/label.js`（getLabelPrompt）、`lib/util/domain-tree.js` | 学科 taxonomy 采用**二级树**；支持「rebuild / revise / keep」三种演进动作（revise＝增量合并） |
| **问题二次 LLM 分类**：先生成问题，再单独一次 LLM 调用做标签匹配；规则＝优先匹配二级标签、兜底"其他"、**标签必须存在于标签库** | `lib/llm/prompts/addLabel.js` | 分类提示词的核心约束照搬：白名单 + 优先二级 + 兜底类；输出 question+label 对数组便于批量 |
| **标签树与题目通过 label 字符串关联**（非外键），伪标签 `uncategorized` 表示未归类 | `prisma/schema.prisma`（Tags/Questions.label） | 分类注记文件同样以 label 字符串关联，简单直接；"未分类"显式成类，统计不丽数 |
| **质量与人工状态字段**：`score`(0–5)、`aiEvaluation`、`confirmed`(人工确认) | Datasets 模型 | 分类结果同样带 `confidence` + `confirmed`（人审后置真），支撑抽样人审闭环 |
| **监控统计**：token 趋势（按小时/天）、模型分布、成功率/失败率、平均延迟，统计卡片 + 图表 + 明细表 + CSV 导出 | `app/api/monitoring/stats`、`app/monitoring/page.js` | 仪表盘布局范式：**汇总卡 → 趋势/分布图 → 明细表 → CSV 导出**；LLM 调用也记 usage 日志 |
| **并发与任务**：`processInParallel`（滑动窗口限并发），任务可中断恢复 | `lib/util/async.js`、Task 状态机（0处理中/1完成/2失败/3中断） | 分类批任务的并发模型与断点续跑（按内容哈希缓存） |
| **CoT 提取与导出**：`<think>` 包裹或 `reasoning_content` 字段抽取为 `cot`；导出时可拼回答案或独立字段 | `lib/llm/core/index.js`、`useDatasetExport.js` | 思考长度统计口径定义参考：**独立字段口径**（本家族已是独立字段，天然适配） |

### 2.2 distilabel（Argilla，Python/Pydantic）

| 其做法 | 事实依据 | qa-stats 借鉴 |
|---|---|---|
| **三段式步骤抽象**：GeneratorStep（数据源）→ Step（逐批处理）→ GlobalStep（全量聚合，强制走文件系统） | `distilabel.steps.base` | 分析管道分三层：**载入适配层 → 逐题指标层（流式）→ 全量聚合层**，语义对应 |
| **列契约 + 列名映射**：`inputs/outputs` 声明必需列并自动校验；`input_mappings/output_mappings` 把外部列名映射到内部约定列 | Step 基类 | research/factual 两种 schema 的差异用**一张列映射表**抹平（如 reasoning 只在 factual 存在，声明为可选列） |
| **TextClassification 任务**：`available_labels` 白名单（列表或"标签→描述"字典）注入提示词，默认结构化输出约束为 JSON，配 `default_label` 兜底 | components-gallery/tasks/TextClassification | LLM 分类的标准形态：**标签白名单 + 每标签一句描述**（比光秃标签更稳）+ 兜底类 |
| **结构化输出与容错**：API 模型走 instructor（`response_model` + `max_retries` 重试）；解析失败**不丢数据**——输出列置 None、原文保留进 metadata | structured_generation 指南 | 分类解析失败降级为 `null + 原因`，原始响应存入注记文件的 debug 字段，可回查 |
| **评分范式**：`rating + rationale` 成对输出，aspect 参数化（同一 judge 类多维度复用） | UltraFeedback / PrometheusEval | 分类输出附 `reasons`（一句话依据），人审时可见"为什么这么分" |
| **签名驱动缓存**：管道签名（结构+参数）一致则命中缓存，只重算变化部分 | caching 指南 | 分类缓存键 = **题目内容哈希 + taxonomy 版本 + 提示词版本**，taxonomy 迭代后自动增量重分类 |
| **Argilla 人审集成**：边生成边推送人审，LLM 判断作为 suggestion 预填，人工只校对 | argilla how-to-guide | 人审队列里 LLM 分类作为**预填答案**，人工一键确认/改判（conf 提升、进入 confirmed） |
| **明确缺口**：distilabel 与 Argilla v2 **均不提供**数据集分布统计/仪表盘（v1 metrics API 已移除） | Argilla v2 release notes | 佐证：统计可视化层必须自建，正是本项目的价值空间 |

> 调研还澄清了一个常见误传：easy-dataset 当前版本（≥1.3）已用 Prisma+SQLite 存储，所谓 `totalFiles/totalChunks/totalQuestions` 汇总统计接口在当前 main 分支并不存在（只有 monitoring 统计），设计中不照搬该接口形态。

### 2.3 一句话总结

- **easy-dataset 给了"分类体系怎么建、怎么给题打标"的范式**（二级树 + 白名单约束 + 标签树可编辑）；
- **distilabel 给了"管道怎么组织、LLM 输出怎么约束、缓存怎么命中"的工程范式**（列契约、结构化输出、签名缓存、失败不丢数据）；
- 两者的**统计可视化都是空白**——本项目在该层完全自建，反而没有历史包袱。

## 3. 总体架构

```
                    ┌─────────────────────────────────────────────────────┐
                    │                     web（ECharts 仪表盘）              │
                    │   概览卡 / 交互筛选 / 图表区 / 明细表 / 分类人审队列 / 设置  │
                    └──────────────────────────┬──────────────────────────┘
                                               │ HTTP (家族风格 REST)
┌──────────────────────────────────────────────┴──────────────────────────────────────┐
│                                            server                                    │
│                                                                                      │
│  scanner ──► loader/adapter ──► unify（统一行模型 + 列映射） ──► metrics（逐题指标层）   │
│  （扫盘找       （读 -qa.jsonl，      （research/factual               （长度/token/      │
│   -qa.jsonl）     双 schema 识别）      差异抹平，可选列声明）            质量指标，纯程序）  │
│                                                                                      │
│  ┌──────────────────────── 分类引擎（L0–L3 混合）────────────────────────┐             │
│  │ L0 规则层   正则/关键词/符号密度 → 高置信直接定案 + 先验证据             │             │
│  │ L1 LLM 层  批量调用（OpenAI 兼容），白名单约束 JSON，confidence 自评     │             │
│  │ L2 校验层  合法性/先验冲突/低置信 → 仲裁（judge 模型）或人审队列          │             │
│  │ L3 反馈层  （可选）"其他"类 embedding 聚类 → 提议新标签 → 人工确认       │             │
│  └──────────────────────────────────────────────────────────────────────┘             │
│                                                                                      │
│  cache（内容哈希+taxonomy版本+prompt版本 → 分类结果，断点续跑）                          │
│  aggregator（全量聚合层：分布/分位数/交叉表/相关系数）──► report（MD / 单文件 HTML / PNG）│
│  llm-util（OpenAI 兼容直连 + usage 日志，复用家族实现模式）                              │
└──────────────────────────────────────────────────────────────────────────────────────┘
          │                                    │                              │
          ▼                                    ▼                              ▼
  <stem>-qa-cls.jsonl              <stem>-qa-stats.json              report/（报告目录）
  （分类注记，按 id 关联，            （统计表单）                        qa-report.html
   不改动原 -qa.jsonl）                                                 qa-report.md / *.png
```

三条设计原则：

1. **旁挂不侵入**：所有新产物（分类注记、统计、报告）独立落盘，原 `-qa.jsonl` 永不修改（与家族"浏览产物按 id 自动关联"的模式一致）。
2. **程序优先、LLM 补位**：凡是确定性可得的（gaPair、track、字符长度）一律程序产出；LLM 只做程序做不了的语义判断，且每一步有校验兜底。
3. **一切可增量**：分类结果按内容哈希缓存，taxonomy/提示词升级后只重分类受影响的题。

## 4. 输入契约与统一数据模型

### 4.1 输入识别（loader/adapter）

| 来源 | 每行字段 | 识别特征 |
|---|---|---|
| `q-a-factual`（factual 轨） | `{id, question, label, gaPair, track, chunkIndex, chunkName, model, answer, reasoning, reasoningRaw, finishReason, references[], qCheck, eval}` | 有 `reasoning` + `track` |
| `q-a`（research 轨） | `{id, question, label, gaPair, chunkIndex, chunkName, model, answer, references[], qCheck, eval}` | 有 `references` 且无 `reasoning` |

> 研究轨的 `label` 是 md-q 的**章节角色**（overview/intro/methods/results…），factual 轨的 `track` 是 non-math/math，`gaPair` 是提问角度（fact/relation/synthesize/formula…）。这些是**已有的程序级维度**，直接进入统计；qa-stats 新增的**学科**与**内容类型**两个维度由分类引擎产出。

### 4.2 统一行模型（unify，借鉴 distilabel 列契约）

```js
// 内部统一行（Optional 列缺失时置 null，统计时按维度自动降级）
{
  id, stem, flow,                 // 溯源：文献标识 / research|factual
  question, answer,
  reasoning,        reasoningRaw,    finishReason,   // factual 专有（可选列）
  label, gaPair, track,                              // 上游程序维度
  chunkIndex, chunkName, model,
  references,        // research 专有（可选列）
  qCheck, eval,                                        // 上游质量字段
  // —— 以下由 qa-stats 补齐 ——

  // 逐题指标层（metrics，纯程序）
  len: { qChars, aChars, rChars, rRawChars,
         qTokens, aTokens, rTokens, rRawTokens,      // token 估算，见 §6.1
         aParas, aSents, reasoningAnswerRatio, cleanupCompression },
  flags: { truncated, emptyAnswer, lowScore, refMissing, outlierLen },

  // 分类引擎产物（L0–L2）
  subject:      { l1, l2, confidence, source, confirmed },   // source: rule|llm|judge|human
  contentType:  { type, confidence, source, confirmed },
  reasons: "",                                        // LLM 一句话依据（rationale）
}
```

列映射通过 `config/columns.json` 可覆盖（对应 distilabel 的 `input_mappings`），兼容未来 schema 微调。

### 4.3 输出产物（全部在 `-qa.jsonl` 同目录旁挂）

| 文件 | 内容 |
|---|---|
| `<stem>-qa-cls.jsonl` | 分类注记：每行 `{id, status, subject:{l1,l2,confidence,source}, contentType, reasons, confirmed, needsReview, conflict, error, debug, clsVersion, taxonomyVersion, promptVersion}`（解析失败时值 null + debug 留原始响应，**不丢数据**；`source ∈ rule/llm/llm-judge/human`） |
| `<stem>-qa-clsmeta.json` | 分类运行元数据：计数（缓存命中/规则定案/LLM/judge/待人审/失败/中断）、token 用量、耗时 |
| `qa-stats-report/qa-report.html` | 单文件交互报告（内嵌 ECharts，双击可看、可分享，零依赖） |
| `qa-stats-report/qa-report.md` | Markdown 报告（表格 + 自动要点 + 口径脚注） |
| `qa-stats-report/tables/*.csv` | 12 个维度明细表（供 Excel 二次分析） |
| `qa-stats-cache/<stem>-cls.json` | 分类缓存（内容哈希 + taxonomy 版本 + 提示词版本 三重键 → 结果），断点续跑用 |

## 5. 分类体系设计（taxonomy）

### 5.1 学科 taxonomy（二级树）

存储 `presets/taxonomy.json`（可编辑、带版本号，对应 easy-dataset 的 Tags 树 + 其标签管理 API）：

```json
{
  "version": 3,
  "dimension": "subject",
  "tree": [
    { "label": "物理海洋学", "desc": "海水的温度盐度密度、环流、波浪与潮汐",
      "children": [
        { "label": "海洋环流", "desc": "风生环流、温盐环流、涡旋与输送" },
        { "label": "波浪与潮汐", "desc": "表面波、内波、潮汐理论与观测" }
      ] },
    { "label": "气象学与气候", "desc": "大气结构、天气系统、气候动力学",
      "children": [ { "label": "大气动力", "desc": "" }, { "label": "气候变率", "desc": "" } ] },
    { "label": "海洋化学", "desc": "" },
    { "label": "海洋生物地球化学", "desc": "碳循环、营养盐、元素循环与通量" },
    { "label": "数学与统计方法", "desc": "微积分、线性代数、概率统计在海洋气象中的应用" },
    { "label": "观测与数据分析", "desc": "仪器、遥感、数据处理与可视化方法" },
    { "label": "其他", "desc": "无法归入以上学科的题目（兜底类）" }
  ]
}
```

构建方式（两来源，运行期可切换）：

- **A. 预置**：针对海洋气象语料（ocean-met-textbooks 家族）内置上表，直接可用（M2 默认）；
- **B. 归纳**：easy-dataset 式——把全部文献的 `chunkName`（章节名）+ 每文献抽样 30 问喂给 LLM，产出二级树**建议稿**，人工在设置页确认/修改后生效（M4；对应其 `getLabelPrompt`：一级 5–10、二级 1–10、≤6 字、严格 JSON）。taxonomy 变更走版本号 + `revise`（增量合并，对应其 labelRevise 提示词），已分类结果按缓存键自动失效重分类。

### 5.2 内容类型 taxonomy（一级，封闭集）

```
概念定义 | 机理过程 | 数值计算 | 关系比较 | 方法流程 | 应用实例 | 证据引用 | 综合论述 | 其他
```

与 `gaPair`（提问角度）**相互独立但可交叉验证**：`fact` 角度的题多落"概念定义"，`formula` 必落"数值计算"，`relation` 多落"关系比较"，`synthesize` 多落"综合论述"——L0 规则层据此给出先验，统计层出 gaPair × contentType 交叉表检验一致性（大幅偏移即分类异常信号）。

## 6. 混合分类引擎（核心设计）

### 6.1 逐题指标层（metrics，纯程序，零 LLM）

- **长度**：字符数（中英统一按 code unit）；token 估算 `ceil(chars / 3.5)`（家族已有系数；可选接 tiktoken/cl100k 精确化，配置开关）。
- **思考双口径**：`rChars`（reasoning，梳理后，语料口径——**主口径**）与 `rRawChars`（reasoningRaw，原始）；`cleanupCompression = 1 − rChars/rRawChars`（梳理压缩率，衡量噪声剔除量）；`reasoningAnswerRatio = rTokens/aTokens`（思考/答案比）。
- **标志位**：`truncated`（finishReason=length）、`emptyAnswer`、`lowScore`（eval 低于阈值）、`refMissing`（research 轨 references 为空）、`outlierLen`（长度超出 P1–P99 区间）。

### 6.2 L0 规则层（确定性，即时，覆盖率高）

| 规则 | 输出 | 置信度 |
|---|---|---|
| `gaPair=formula` 且数学符号密度 ≥ 阈值（=、∑、∫、%、带单位数值 占比） | contentType=数值计算 | 0.95，直接定案 |
| `gaPair=fact/relation/synthesize` → 映射表（fact→概念定义等） | contentType 先验 | 0.5–0.7（仅作先验，交 L1/L2） |
| `track=math`（factual） | contentType=数值计算 先验 | 0.7 |
| 文献名/chunkName 关键词命中（如书名含 marineCarbonBGC → 海洋生物地球化学；章节名 "Tides" → 物理海洋学/波浪与潮汐） | subject 先验 | 0.6–0.9（书级强、章级中） |
| 题面关键词字典（潮汐/环流/海气通量/回归/方差分析…→ 对应学科） | subject 先验 | 0.5 |

规则结果分两类：**定案**（conf ≥ 0.9，跳过 LLM，省钱省时）与**先验**（附在题上，供 L1 提示与 L2 校验）。规则全部集中在 `server/rules.js`，字典可配置，`npm test` 可覆盖。

### 6.3 L1 LLM 层（批量语义分类）

调用形态（OpenAI 兼容直连，复用家族 `llm-util` 模式；温度 0）：

- **批量**：每批 10–15 题，一次调用返回数组（easy-dataset addLabel 同款形态），只传 `id + question + answer 前 400 字符 + chunkName + 先验`，控制上下文成本；
- **白名单约束**（easy-dataset + distilabel TextClassification 同款）：提示词内嵌完整 taxonomy（**标签 + 一句描述**），声明"标签必须取自给定清单，优先二级，无法判断用 兜底类"；
- **结构化输出**：JSON 数组 `[{id, subject:{l1,l2}, contentType, confidence, reasons}]`；服务端二次校验（JSON 修复一次 → 失败则该批降为单题重试 → 仍失败置 null + debug 存原始响应，**不丢数据不阻塞**）；
- **自评置信度**：要求模型输出 confidence ∈ [0,1]，校验层与规则先验交叉使用。

提示词骨架（存 `server/prompts.js`，支持设置页预览，零 LLM 调用——沿用家族"提示词预览"惯例）：

```
你是语料标注专家。请为每道题选择【学科】（二级：优先细类，匹配不到再选一级，
都不匹配选"其他"）和【内容类型】。

学科清单（label: 描述）：
{{taxonomyTree}}
内容类型清单：概念定义: … | 机理过程: … | …（逐项一句描述）

规则：
1. 标签必须严格取自上述清单，禁止编造；
2. 结合题面、答案要点与来源章节（chunkName）判断；已给出的先验仅供参考，可推翻；
3. confidence 为你的把握程度（0~1）；
4. 仅输出 JSON 数组，每元素 {"id","subject":{"l1","l2"},"contentType","confidence","reasons"}，
   reasons 用一句话说明依据。

题目：
[{"id":…, "q":…, "a(截断)":…, "chunk":…, "prior":{…}}, …]
```

### 6.4 L2 校验与仲裁层

对 L1 输出逐条过闸（全部为程序逻辑，零额外成本除仲裁调用）：

1. **合法性**：l1/l2/contentType ∈ 白名单；l2 必须属于其 l1；非法 → 用规则先验纠偏，无先验则进仲裁；
2. **先验冲突**：与 L0 高置信先验（≥0.9）冲突 → 标记 `conflict`，进仲裁；
3. **低置信**：confidence < 0.6 → 进仲裁；
4. **仲裁**：优先**换 judge 模型**单题重判（DeepSeek/local 互换，家族 primary/judge 双模型惯例）；仍低置信/冲突 → 进入**人审队列**（Web 页面，LLM 结果作预填答案 + reasons 展示，人工一键确认或改判 → `confirmed=true, source=human`，对应 Argilla suggestion 预填人审的形态）；
5. （可选高价值子集）**自一致性投票**：对抽样集温度>0 采样 3 次投票取多数，报告投票一致率作为分类可信度指标（distilabel 无内建，自建）。

### 6.5 缓存与断点续跑（借鉴 distilabel 签名缓存）

```
cacheKey = sha256(question + answer前400字 + chunkName)
cacheVal = {subject, contentType, confidence, source, reasons, taxonomyVersion, promptVersion}
命中条件：cacheVal.taxonomyVersion === 当前版本 && promptVersion === 当前版本
```

- taxonomy/提示词升级 → 全量自动失效，增量重分类（只调未命中的题）；
- 任务中断 → 已分类批次保留（缓存放 `qa-stats-cache/`，逐批落盘），续跑从缺口开始；
- 并发用家族同款滑动窗口（`processInParallel` 模式），默认并发 2–3，设置页可调；
- 每次 LLM 调用记 usage（入/出 token、延迟、成败）进 `qa-stats-meta.json`，仪表盘有 token 消耗卡（easy-dataset monitoring 同款）。

### 6.6 L3 聚类反馈层（可选，M4）

对落入兜底"其他"的题与全部低置信题，本地或 API 计算 embedding → 简单聚类（k-means，纯 JS 实现）→ 每簇取 Top 关键词让 LLM 命名 → 产出"新标签建议"列表，人工确认后 `revise` 进 taxonomy。目的：**让分类体系从语料中长出来**，而不是一次拍死。

### 6.7 分类质量评估（写进报告，诚实呈现）

- 抽样 N=100 的人审一致率（accuracy vs 人判）；
- LLM 自评置信度分布直方图（大量低置信 = taxonomy 不适配的信号）；
- "其他"类占比（>10% 触发 L3 建议新标签）；
- 先验冲突率、仲裁率、人审待办数；
- 自一致性投票一致率（若启用）。

## 7. 统计分析指标体系

### 7.1 指标总表

| 板块 | 指标 | 主展示形式 |
|---|---|---|
| **规模概览** | 文献数、QA 总数、各文献 QA 数与占比、每文献平均分/块 | 汇总卡 + 条形图 |
| **学科分布** | 一级/二级学科计数与占比、"其他"占比、各文献的学科构成对比 | 旭日图 + 交叉表 |
| **内容分类** | contentType 分布、gaPair 分布、**gaPair × contentType 一致性交叉表**（分类自检信号） | 堆积条形 + 热力表 |
| **思考长度（主口径 reasoning）** | 分布直方图（可切 rRawChars 原始口径）；分位数表 P25/P50/P75/P90/P95 + mean/std/min/max；**按 track / 学科 / contentType / gaPair 分组箱线图**；思考/答案比分布；梳理压缩率分布 | 直方图 + 箱线图 + 表 |
| **截断偏差** | finishReason=length 占比；截断组的长度分布 vs 非截断组（提示截断样本长度被系统性低估）；截断按文献/模型分组 | 分组条形 + 标注 |
| **质量** | eval 分数分布（直方图）；qCheck 各子项通过率（accuracy/completeness/citations_ok 或 factual_ok）；低分题清单；research 轨空引用率 | 直方图 + 表 |
| **交叉分析** | 学科 × contentType 热力图；思考长度 × eval 分数散点（含相关系数 r，判断"想得越长答得越好"是否成立）；答案长度 × 思考长度散点 | 热力图 + 散点 |
| **异常清单** | truncated / emptyAnswer / outlierLen / lowScore / refMissing / 低置信分类 各计数 + 明细导出 | 表 + CSV |

### 7.2 统计口径约定（写死在代码与报告脚注）

- 长度默认**字符数**；token 为估算值（÷3.5），报告中标注"估算"；
- 思考长度默认 **reasoning（梳理后）口径**，所有思考长度图表提供"原始（reasoningRaw）"切换；无 reasoning 的 research 轨自动隐藏该板块并在报告中标明原因；
- 分组箱线图必须标注各组 n（小于 30 的组加"样本少"提示）；
- 相关系数用 Pearson（列明），非线性关系肉眼从散点判断。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 分类标签漂移/编造标签 | 统计失真 | 白名单硬约束 + 合法性校验兜底纠偏 + 温度 0 + 缓存固定结果 |
| taxonomy 与语料不适配（大量落"其他"） | 学科分布无信息量 | "其他"占比阈值告警 + L3 聚类建议新标签 + revise 增量演进 |
| 批量 JSON 解析失败 | 批次报废 | JSON 修复一次 → 单题降级重试 → null+debug 不丢数据（distilabel 同款容错） |
| taxonomy 迭代引发全量重分类成本 | token 浪费 | 缓存键含 taxonomyVersion，只重算未命中题；先验强的题 L0 定案不花 LLM |
| 截断样本使思考长度统计偏低 | 误导结论 | 截断组独立统计 + 报告显著标注；箱线图可排除截断组切换 |
| token 估算误差（字符/3.5） | 长度口径粗糙 | 报告标注"估算"；提供 tiktoken 精确开关（需联网装依赖，默认关） |
| research 轨无 reasoning 字段 | 思考长度板块缺失 | 可选列设计自动降级，报告明示"该语料无思考字段" |

## 12. 附录：与参考项目的机制对照

| 机制 | easy-dataset | distilabel | qa-stats 采用 |
|---|---|---|---|
| 分类体系 | 两级标签树（TOC 归纳，可编辑，revise 增量） | — | 二级学科树（预置+归纳+revise）✔ 其形态 |
| 单题打标 | 二次 LLM 调用 + 白名单 + 兜底"其他" | TextClassification：available_labels+描述+default_label | 两者合并：白名单+描述+兜底类 |
| 输出约束 | 提示词约束 JSON + extractJsonFromLLMOutput | instructor/outlines 结构化 + 重试 | 提示词约束 + JSON 修复 + 单题降级（务实折中） |
| 失败处理 | 失败返回空不抛错 | 输出置 None、原文进 metadata | null + debug 字段存原文 ✔ distilabel |
| 结果可信 | score + confirmed 人工确认 | Argilla 人审 + suggestion 预填 | confidence + confirmed + 人审队列预填 |
| 缓存/续跑 | 分块缓存 + 任务恢复 | 签名缓存 + SIGINT 续跑 | 内容哈希 + 版本键缓存 + 逐批落盘 |
| 统计可视化 | 仅 LLM usage 监控（token/模型/失败率） | 无（Argilla v2 已移除 metrics） | **全维度统计 + 仪表盘 + 报告（本项目主体）** |
| 管道组织 | 服务化任务（11 种 taskType） | Step DAG + 列契约 + GlobalStep 聚合 | 载入→逐题指标→全量聚合三层（取其语义，不引入 DAG 框架） |
